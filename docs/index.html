Your first connection.
Two ways in.

Use your Azure account or connect directly to a namespace. Start with the connection method that fits your environment.

Sign in with Azure

Use Azure Identity to discover subscriptions and namespaces available to your account.

  1. Sign in to Azure.
  2. Select your subscription and namespace.
  3. Open a queue or subscription to browse messages.

Required access depends on your operation. The README prerequisites list Reader, Azure Service Bus Data Receiver, and Azure Service Bus Data Sender.

Use a connection string

Connect directly with a Service Bus connection string and keep saved connections in your library.

  1. Open the connection library.
  2. Add or select a connection.
  3. Browse entities and open your workspace.

Saved connection strings use AES-256 encryption with machine-specific keys. Choose credentials with permissions for your intended operations.

A lock for your workspace.

Optional app lock adds a launch-time password gate, a recovery code, and Touch ID or Windows Hello shortcuts where supported. Enable it in Settings → Security and save your recovery code.

A few useful details.

Does peeking remove messages?

No. Peek is read-only. Settlement actions require receiving messages under a lock first; actions depend on the broker lock remaining valid.

Can I manage every scheduled message?

The scheduled-message console indexes messages scheduled through BusLane. Azure Service Bus does not provide an API to enumerate all scheduled messages. Refresh reloads the local index; it cannot confirm that a schedule still exists at the broker. Read the workflow details.

Where are setup and usage instructions?

The repository README covers installation, prerequisites, connection modes, and app lock. Start there for platform-specific installation notes.

How can I contribute or report a problem?

Report a bug or request a feature, or fork the repository and open a pull request. For sensitive security reports, follow the security policy.
